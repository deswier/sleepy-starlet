What vercel.json does

Single-line rewrite that hands every URL to index.html. Without it, hitting https://your-app.vercel.app/auth directly (or refreshing on any non-root route) would 404 because Vercel looks for an auth.html file. Vite SPAs always need this; Vercel's Vite preset usually adds it        
automatically, but having it explicit is insurance.

1. https://vercel.com/signup → continue with GitHub.
2. Dashboard → Add New → Project.
3. Find sleepy-starlet in the GitHub list → Import.                                                                                                                                                                                                                                       
   - If the repo isn't listed: Adjust GitHub App Permissions → grant access to this repo.

Vercel auto-detects Vite. Defaults that should already be filled in:

Expand Environment Variables and add the same three from your .env:

├───────────────────────────────┼────────────────────────────────────┤

└───────────────────────────────┴────────────────────────────────────┘

Set environment to Production, Preview, and Development (the default — all three checkboxes ticked). Without these the app builds but loads as a blank page because createClient gets undefined.

4. Deploy

Click Deploy. First build takes ~90 seconds. You'll get a URL like sleepy-starlet-abc123.vercel.app.

5. Update Supabase to allowlist the new domain

Authentication → URL Configuration:
- Site URL → change from http://localhost:8080 to your new Vercel production URL: https://sleepy-starlet.vercel.app (or whatever Vercel gave you — the bare project URL, not the per-deploy URL)
- Additional Redirect URLs → add:                                                                                                                                                                                                                                                         
  https://sleepy-starlet.vercel.app                         
  https://sleepy-starlet.vercel.app/**                                                                                                                                                                                                                                                      
  https://*-sleepy-starlet.vercel.app/**
- The wildcard line covers branch/PR preview URLs (sleepy-starlet-git-feature-x.vercel.app) so OAuth works on those too.

Save.

6. Update Google OAuth too

Google Cloud Console → Credentials → your OAuth client → Authorized redirect URIs:
- Already has https://<supabase-ref>.supabase.co/auth/v1/callback — that stays.
- Nothing new needs to be added here. Google only cares about the Supabase callback, which is the same. Vercel domains never appear in Google's allowlist.

7. Verify

1. Open https://sleepy-starlet.vercel.app/auth on your laptop.
2. Sign up with email → should work.
3. Sign in with Google → should redirect to Google → back to your Vercel domain → signed in.
4. Open the same URL on your phone → Share → Add to Home Screen → opens fullscreen with the manifest icon. That's your "Lovable preview replacement" — bookmark this flow.

8. Per-branch preview URLs

This is the part you actually wanted from Lovable. Now:

git checkout -b feature/foo
# make changes
git push -u origin feature/foo

Within ~60s you'll get a comment in your PR (or in the Vercel dashboard's Deployments tab) with a unique URL like sleepy-starlet-git-feature-foo-yourname.vercel.app. Test on your phone, share with whoever, merge → production updates automatically.

Caveats

Two lockfiles. Your repo has both bun.lockb and package-lock.json. Vercel will pick one based on detection priority — I think bun first, but it can be inconsistent. If you ever see a "Cannot find module" error on Vercel that doesn't reproduce locally, lock it down explicitly: in   
Project Settings → General → Install Command → set to npm install or bun install so it stops auto-guessing.

Custom domain (optional). Project Settings → Domains → Add. Vercel handles SSL and DNS instructions. Don't forget to add the custom domain to Supabase's redirect allowlist when you do this.

Auto-deploy hot wiring. Every push to main deploys to production. If you don't want that, Project Settings → Git → uncheck "Production Branch auto-deploy" and trigger manually instead.

❯ what Application Preset I should choose

⏺ Vite.

Vercel auto-detects it from your vite.config.ts, but if it asks anyway pick Vite from the dropdown. With that preset, the Build Command (vite build), Output Directory (dist), and Dev Command get set automatically — leave them blank/default.

Don't pick "Other" or "Create React App" — those use different defaults that won't match your dist/ output.
